## 功能缺陷（需修复或明确范围）

**TLS-3-3 X25519 传统密钥交换回退验证**：交付包配置校验直接拒绝纯 X25519 组，报
`unsupported PQ group "X25519"`，无法完成传统密钥交换回退。

- 证据：`tls-test-scripts-gateway/results/run-20261022-155551-5/TLS-3-3/step-1.out`、`analysis/finding-不支持纯X25519回退.txt`
- 影响：若交付范围包含"混合算法不可用时回退到传统 X25519"，则该项不满足；若交付包只承诺混合/抗量子组，应在验收范围中明确排除该用例。

## 暂停项（需要源码才能运行，未判定通过/失败）

| 用例 | 原因（所需源码程序） |
|---|---|
| TLS-1-9 无效密钥交换组处理 | 需 `.build/client` 的 `DummyKex`（probe 不支持）。附观测：交付包对未知组返回 `handshake_failure`，未实现 HelloRetryRequest |
| TLS-1-13 异构 Sig/KEM 认证 | 需 `go_kemtls` + `cloudflare_server/client` 源码 |
| TLS-2-1～2-4 单连接/并发耗时 | 需 `.build/tlsbench`（probe 不支持 `-n` 重复与 `-c` 并发） |
| TLS-3-2 ExportKeyingMaterial | 需 `.build/e2e` 的密钥导出能力（probe 不暴露密钥材料） |
| TLS-3-4 Linux 编译运行 | 需源码 `go build tls-hybrid/server、tls-hybrid/client` |
| TLS-3-5 Windows 交叉编译 | 需源码 `GOOS=windows go build` |

## 其他执行说明

- TLS-1-10：有效证书、无关 CA 两项已执行；"过期证书"步骤因交付包 demo 证书均在有效期、证书工具不提供过期证书配置而 SKIP。无关 CA 被拒绝时的实际报错为 `PQ public key algorithm mismatch`。
- TLS-1-12：6 组 key_share 拼接长度全部与大纲一致（865/897、832/800、1216/1120、1600/1600、2281/4465、7277/14453）。
- TLS-2-7：交付包 probe 单次一个连接，按每档 20 次执行（`GW_NETEM_N`），4 档时延（0/2/25/100 ms）全部成功；中间盒三策略因缺 `tools/tls_middlebox.py` 仍 SKIP。
- TLS-1-8：交付包对 TLS 1.2、畸形版本、无共同组分别返回 protocol_version / handshake_failure 告警，符合预期。
