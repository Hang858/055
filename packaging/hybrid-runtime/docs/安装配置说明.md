# 安装和配置说明

## 1. 安装

目标机为 Ubuntu 20.04 / x86_64。需要`unzip`、`sha256sum`和`bash`；运行`smoke.py`时需要 Python 3。程序已静态链接，运行时不需要 Go 或 liboqs。

```sh
unzip pqc-gateway-hybrid-mlkem-ubuntu20.04-amd64-20261013.zip
cd pqc-gateway-hybrid-mlkem-ubuntu20.04-amd64-20261013
sha256sum -c SHA256SUMS
sudo ./install.sh /opt/pqc-gateway-hybrid
```

安装脚本拒绝覆盖已有目录，不会自动启动网关。下文命令均在安装目录执行。

## 2. 生成厂内证书

在受控机器上复制`config/certtool-44.json`或`config/certtool-87.json`。把`output_dir`改成尚不存在的`../certs/44`或`../certs/87`；修改根证书名称和服务端`dns_names`、`ip_addresses`。这些 SAN 必须包含客户端访问网关时使用的域名或 IP。运行：

```sh
cp config/certtool-44.json config/certtool-site-44.json
# 编辑 config/certtool-site-44.json：output_dir、common_name、dns_names、ip_addresses
bin/pqc-certtool check -config config/certtool-site-44.json
bin/pqc-certtool generate -config config/certtool-site-44.json
bin/pqc-certtool verify -config config/certtool-site-44.json
```

`generate`每次创建全新目录，不覆盖已有证书。正式环境应把根 CA 私钥离线保存；网关只需`root.crt`、`server.crt`、`server.key`和`server.pq.key`。启用双向认证时，客户端另需`client.crt`、`client.key`、`client.pq.key`及信任根`root.crt`。不要把客户端私钥和根 CA 私钥留在网关运行目录。私钥权限设为`0600`，并只给运行该程序的账户读取权限。

## 3. 配置和启动网关

`config/gateway-44.json`对应 ML-DSA-44 与 SM2MLKEM512；`config/gateway-87.json`对应 ML-DSA-87 与 SM2MLKEM1024。配置中的`cert`、`key`、`pq_key`、`root_ca`和`client_ca`是相对配置文件所在目录的路径。修改`listen`、`upstream`、`server_name`和证书路径；`server_name`必须与服务端证书 SAN 一致。SM2MLKEM 组使用私有码点，客户端也须使用配套程序。

`client_ca`指定受信任的客户端根证书。保留该字段就必须提供 SM2+ML-DSA 客户端证书；删除该字段则仅验证网关服务端身份。若客户端证书由另一根 CA 签发，把`client_ca`改成该根证书。中间 CA 用`intermediates`按根到叶顺序填写。`upstream`可为 HTTP 或 HTTPS；HTTPS 上游可用`upstream_ca`和`upstream_server_name`配置校验。

```sh
bin/pqc-gateway check -config config/gateway-44.json
bin/pqc-gateway serve -config config/gateway-44.json
```

使用 HQC 时，改用`bin/pqc-gateway-hqc`和`config/gateway-44-hqc.json`或`gateway-87-hqc.json`。HQC 与签名算法分别配置，双签认证规则不变。

## 4. 客户端验证

客户端使用本包内同一档位的程序和 CA 证书。连接 IP 时用`-server-name`指定证书中的 DNS 名称；若证书仅含 IP SAN，则填对应 IP。

```sh
bin/pqc-gateway probe -url https://127.0.0.1:8443/ \
  -server-name gateway.factory.local -ca certs/44/root.crt \
  -auth sm2-mldsa-44 -kex SM2MLKEM512 \
  -cert /path/to/client.crt -key /path/to/client.key \
  -pq-key /path/to/client.pq.key -client-ca certs/44/root.crt
```

客户端有中间 CA 时，加`-client-intermediates ca1.crt,ca2.crt`，顺序为根到叶。成功输出包含`negotiated_kex`、`authenticated_signature`、私有码点和 HTTP 状态。客户端不提供证书、信任根不匹配、两份签名有一份出错或档位不一致时，连接应失败。

传统 ECDSA 服务可用独立配置和端口运行；混合认证端口只接受配置指定的双签档位，不回退到传统认证。浏览器不在此交付范围内。

## 5. 作为系统服务运行

`systemd/pqc-gateway-hybrid.service`是使用 44 档和`/opt/pqc-gateway-hybrid`路径的模板。先按第 2 节移走根 CA 与客户端私钥，再创建运行账户、授予网关证书目录的读取权限并安装服务文件：

```sh
sudo useradd --system --no-create-home --shell /usr/sbin/nologin pqc-gateway
sudo chown -R pqc-gateway:pqc-gateway /opt/pqc-gateway-hybrid/certs/44
sudo chmod 700 /opt/pqc-gateway-hybrid/certs/44
sudo install -m 644 systemd/pqc-gateway-hybrid.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now pqc-gateway-hybrid
sudo journalctl -u pqc-gateway-hybrid -f
```

已有`pqc-gateway`账户时跳过`useradd`。使用 87 档、HQC 或其他安装路径时，先修改服务文件中的程序路径和配置路径。启用服务前先运行上面的`check`命令。
