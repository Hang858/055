## 常见故障

| 现象 | 排查和处理 |
|---|---|
| Exec format error | uname -m 应为 x86_64；ARM64 使用另行构建的包 |
| 服务不能启动 | journalctl -u pqc-gateway；用服务账号执行 check，检查 JSON、文件路径/权限和证书有效期 |
| address already in use | ss -lntp 检查端口占用；变更 listen 并重启 |
| permission denied | 检查证书父目录可进入、server.key 对服务组可读；systemd 文件已有低端口绑定 capability |
| certificate signed by unknown authority | probe 使用现场 ca.crt；确认服务端链含所需中间 CA |
| certificate is valid for ... | 使用证书 SAN 中的名称/IP；修改 DNS/hosts 或重新签发，不关闭校验 |
| 证书过期/尚未生效 | 检查双方机器 date 时间；换用有效证书，重启后重新验收 |
| no supported ... / handshake failure | 客户端和服务端至少启用一个相同 Draft00 组；先用包内 probe；mTLS 检查客户端证书 |
| 502 Bad Gateway | 网关已完成入站握手；检查后端 IP/端口、网络、证书 CA 和域名；查看 upstream error 日志 |
| 404/业务登录失败 | 检查业务路径及后端日志；网关将 Host 改为后端地址，需业务匹配相应虚拟主机配置 |
| 重定向后访问原业务地址 | 后端绝对 Location/Cookie Domain 没有自动改写；在业务服务配置外部网关域名，核实登录流程 |
| 只有旧证书/配置生效 | 配置与证书需要 restart；reload 不会生效 |

本交付仅提供固定后端代理，没有速率控制、认证门户或 WAF。业务认证由后端应用负责；初次上线应完成实际登录、Cookie、重定向、上传和长连接场景验证。代理仅设请求头/空闲和后端连接/响应头超时，没有全请求/响应体时限，应按厂内负载与网络策略配置外围连接和访问控制。

## 日志、证书和变更管理

服务通过 journald 记录监听地址、固定后端、实际协商 KEX 和错误，不记录业务正文、私钥或 TLS 会话密钥。日志中的协商事件表示已选择算法，完成握手/验证并成功转发还需结合 probe 返回状态判断。

每次变更保留配置版本及证书有效期，提前安排证书更新；本工具不自动续期。mTLS 使用标准 CA 校验，不实现 CRL/OCSP 自动吊销查询，需要撤销某个客户端身份时应结合厂内 PKI/访问控制方案处理。CA 私钥应离线保管，演示和研究私钥不得复用为正式身份。
