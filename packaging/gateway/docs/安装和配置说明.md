# 安装和配置说明

适用：Ubuntu 20.04，x86_64，Bash；服务托管使用系统自带 systemd。运行二进制为 `CGO_ENABLED=0` 静态构建，无需额外密码库、Go 或互联网。ARM64 需另行构建。本说明中的业务地址为示例，请替换为现场地址。

## 1. 解压和检查

将交付压缩包拷到厂内机器。在压缩包所在目录执行：

```bash
sha256sum -c pqc-gateway-ubuntu20.04-amd64.tar.gz.sha256
tar -xzf pqc-gateway-ubuntu20.04-amd64.tar.gz
cd pqc-gateway-ubuntu20.04-amd64
sha256sum -c SHA256SUMS
./bin/pqc-gateway version
```

所有文件应显示 `OK`。记录压缩包校验值、机器系统/架构和交付版本。压缩包和校验值应由同一受控交付渠道获取。

## 2. 不安装即可本机验证

以下三个终端都进入解压目录。

终端 A：启动包内演示业务服务。

```bash
./bin/pqc-gateway demo-backend -listen 127.0.0.1:9000
```

终端 B：检查配置和启动网关。

```bash
./bin/pqc-gateway check -config config/demo.json
./bin/pqc-gateway serve -config config/demo.json
```

终端 C：使用项目匹配的 PQ 协议客户端访问。

```bash
./bin/pqc-gateway probe -url https://localhost:8443/check -ca certs-demo/ca.crt -kex SM2Kyber512Draft00
./bin/pqc-gateway probe -url https://localhost:8443/order -ca certs-demo/ca.crt -kex X25519Kyber768Draft00 -data 'factory-test-001'
```

预期：`certificate_verified=true`、`http_status= 200`、`negotiated_kex=...`，响应含 `factory-backend-ok`；第二条还应回显 `factory-test-001`。完成后在 A、B 终端按 Ctrl+C。演示证书的 SAN 为 localhost、127.0.0.1、::1，仅用于本机联调；不得部署为厂内正式身份。若演示证书已过期，可在新的目录使用 `pki` 生成并修改演示配置。

## 3. 离线安装

默认安装到 `/opt/pqc-gateway`，不覆盖已存在目录，不自动启用服务：

```bash
sudo bash ./install.sh /opt/pqc-gateway
sudo useradd --system --user-group --no-create-home --shell /usr/sbin/nologin pqc-gateway
```

如账号已存在，使用 `id pqc-gateway` 核实后跳过创建。安装程序不自动复制演示私钥到正式目录。

## 4. 生成现场数字证书

示例网关域名为 `gateway.factory.local`，IP 为 `192.168.10.20`。必须填入技术人员实际访问的名称/IP，避免域名校验失败。

```bash
sudo /opt/pqc-gateway/bin/pqc-gateway pki -out /opt/pqc-gateway/certs -hosts gateway.factory.local,192.168.10.20,localhost,127.0.0.1 -days 365
sudo chown root:pqc-gateway /opt/pqc-gateway/certs
sudo chmod 750 /opt/pqc-gateway/certs
sudo chown root:pqc-gateway /opt/pqc-gateway/certs/server.key
sudo chmod 640 /opt/pqc-gateway/certs/server.key
```

生成：`ca.crt`、`ca.key`、`server.crt`、`server.key`、`client.crt`、`client.key`。网关只需 `server.crt` 和 `server.key`；客户端信任 `ca.crt`。CA 私钥不应留在在线网关，将 `ca.key` 及备用客户端私钥移至厂内受控离线存储，保留权限 600；向验收客户端分发 CA 公钥证书，启用双向认证时额外安全分发 client.crt/client.key。不要分发 ca.key 或 server.key。

本命令用于创建全新本地 CA 和一套服务端/客户端身份，不是现有 CA 的续签命令，也不接入企业 PKI。目录非空时拒绝覆盖。如企业已有 CA，可直接使用其签发的 ECDSA/RSA TLS 服务端证书和匹配私钥；叶证书必须有正确 SAN、serverAuth 用途和有效期，证书链文件顺序为“叶证书 → 中间 CA”，信任根通过客户端 CA 文件提供。

若使用域名，请在厂内 DNS 配置解析；临时联调可在客户端 `/etc/hosts` 添加：

```text
192.168.10.20 gateway.factory.local
```

## 5. 配置厂内业务

```bash
sudo nano /opt/pqc-gateway/config/gateway.json
```

示例配置：

```json
{
  "listen": "0.0.0.0:8443",
  "upstream": "http://192.168.10.30:8080",
  "cert": "../certs/server.crt",
  "key": "../certs/server.key",
  "kex": ["SM2Kyber512Draft00", "X25519Kyber768Draft00"],
  "upstream_ca": "",
  "upstream_server_name": "",
  "client_ca": ""
}
```

| 字段 | 设置方式 |
|---|---|
| listen | 网关本机 IP:端口；0.0.0.0 为所有 IPv4 地址，可改成指定业务网卡地址；也可使用 :443 |
| upstream | 唯一固定 HTTP/HTTPS 后端，可带路径前缀，例如 http://10.0.0.5:8080/app；客户端路径追加其后；不带用户名、密码、查询串或 fragment |
| cert/key | PEM 证书链及私钥；相对路径以 JSON 文件所在目录为基准，不以终端工作目录为基准 |
| kex | 启用的 PQ 混合组列表；不得填 X25519、DummyKex 或未交付的 HQC 组 |
| upstream_ca | HTTPS 后端私有 CA 文件；留空使用系统 CA；始终校验证书，不提供跳过校验选项 |
| upstream_server_name | HTTPS 后端证书/SNI 域名；按 IP 连接而证书签给域名时填写该域名 |
| client_ca | 留空为单向认证；填入 CA 文件则强制验证客户端证书（mTLS） |

HTTPS 后端示例：`upstream` 改成 `https://192.168.10.30:9443`，`upstream_ca` 设为 `../certs/backend-ca.crt`，`upstream_server_name` 设为后端证书 SAN 中的 `app.factory.local`。将 backend-ca.crt 放入指定路径，授权服务账号读取。

入站只支持 TLS 1.3，默认没有传统 KEX 回退。可选择六个组：SM2Kyber512Draft00、SM2Kyber768Draft00、SM2Kyber1024Draft00、X25519Kyber512Draft00、X25519Kyber768Draft00、X25519Kyber1024Draft00。组名大小写必须完全一致。配置的顺序不应作为最终协商算法的唯一证据，应以 probe/握手日志为准。

## 6. 检查、启动和开机自启

```bash
sudo -u pqc-gateway /opt/pqc-gateway/bin/pqc-gateway check -config /opt/pqc-gateway/config/gateway.json
sudo install -m 644 /opt/pqc-gateway/systemd/pqc-gateway.service /etc/systemd/system/pqc-gateway.service
sudo systemctl daemon-reload
sudo systemctl enable --now pqc-gateway
sudo systemctl status pqc-gateway --no-pager
sudo journalctl -u pqc-gateway -n 50 --no-pager
sudo ss -lntp
```

预期服务状态 active (running)，监听配置端口。`check` 检查 JSON、算法、证书/私钥匹配、服务端证书有效期和 CA 文件可解析性；不检查后端可达性，必须继续执行第 7 节。自定义安装路径时，手动修改 service 中 WorkingDirectory、ExecStartPre、ExecStart 的路径。

若启用 UFW，按实际访问网段放行，例如：

```bash
sudo ufw allow from 192.168.10.0/24 to any port 8443 proto tcp
```

核实网关到后端端口可达；不要将演示 9000 端口开放给外网。HTTP 后端为明文链路，须位于受控网络；需链路加密时选 HTTPS 后端。

## 7. 厂内独立验收

在另一台 Linux x86_64 客户端解压相同包，仅复制现场 `ca.crt`，执行：

```bash
./bin/pqc-gateway probe -url https://gateway.factory.local:8443/ -ca /path/to/ca.crt -kex SM2Kyber512Draft00
./bin/pqc-gateway probe -url https://gateway.factory.local:8443/ -ca /path/to/ca.crt -kex X25519Kyber768Draft00
```

用实际业务健康检查 URL 替换 `/`，应返回业务响应且退出码为 0。HTTP 4xx/5xx、TLS 握手或校验失败均退出非零。输出包含实际算法、已校验证书和 HTTP 状态。probe 不自动跟随重定向，收到 3xx 后应检查 Location 并明确访问目标地址。

启用 mTLS：将配置 `client_ca` 设置为 `../certs/ca.crt`，重启网关；不带客户端证书的 probe 应失败，以下调用应成功：

```bash
./bin/pqc-gateway probe -url https://gateway.factory.local:8443/ -ca /path/to/ca.crt -kex SM2Kyber512Draft00 -cert /path/to/client.crt -key /path/to/client.key
```

验收表和故障处理见 `验收与运维.md`。浏览器未包含也未做互通验证，浏览器团队必须支持同一 Draft00 组及码点；仅“支持 PQC”不保证兼容。

## 8. 更新配置和证书

变更前备份现用配置、证书及压缩包校验值；按厂内密钥管理制度保管私钥。用新的目录准备替换证书，检查 SAN、用途和证书链，然后更新 config 中路径。执行 `check` 成功后：

```bash
sudo systemctl restart pqc-gateway
sudo systemctl status pqc-gateway --no-pager
```

重新运行第 7 节。配置和证书不热加载，修改后必须重启。若更换本地 CA，应在切换前向客户端分发新 CA；包内 `pki` 每次新建 CA，不能当作保持原 CA 的续签工具。失败时恢复备份路径并重启，不要通过关闭校验绕过问题。

## 9. 停止与卸载

```bash
sudo systemctl disable --now pqc-gateway
```

确认无需恢复后，由管理员移除 `/etc/systemd/system/pqc-gateway.service`，运行 `sudo systemctl daemon-reload`，归档配置/证书，再按厂内流程删除安装目录和专用账号；安装器不执行自动删除。
