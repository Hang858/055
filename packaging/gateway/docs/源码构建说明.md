# 源码构建说明

运行交付包不需要编译。仅在厂内需要审查、改动或重建时使用本节。

`source/gateway/` 为本次新增网关源码与测试；`source/pqcert/` 保留原项目五个工具的 main.go/go.mod/go.sum，并分别附带 vendor，包含依赖许可证。`source/patches/` 为原项目补丁和说明；`source/patched-go1.22.12-source.tar.gz` 保存本次实际构建所用的完整 Go src/lib 与许可文件，避免仅依赖历史补丁而遗漏本地库改动。所有文件校验值见 SHA256SUMS。

## TLS 工具链和网关

需提前准备 Linux Go 1.20.14+ 引导工具链、C 编译器及常规构建工具；它们不属于离线运行依赖。Go 工具链源码构建通常需要 gcc/Bash，必须由厂内软件源或受控离线介质准备。创建工作目录：

```bash
mkdir -p /tmp/pqc-gateway-build
cd /tmp/pqc-gateway-build
tar -xzf /path/to/bundle/source/patched-go1.22.12-source.tar.gz
cd go/src
GOROOT_BOOTSTRAP=/path/to/bootstrap-go ./make.bash
```

上述源码已经打好补丁，不要重复应用 patch。随后使用此工具链：

```bash
export GOROOT=/tmp/pqc-gateway-build/go
export PATH="$GOROOT/bin:$PATH"
export GOTOOLCHAIN=local
export GOPROXY=off
export CGO_ENABLED=0
cd /path/to/bundle/source/gateway
go test ./...
go build -trimpath -ldflags '-s -w' -o /tmp/pqc-gateway-rebuilt .
/tmp/pqc-gateway-rebuilt version
```

测试会监听临时回环端口，需在允许本机网络的环境运行。不要用系统原版 Go 编译网关，原版 crypto/tls 没有本项目组和事件接口。HQC 不在本交付构建范围。

## 原证书工具

需提前准备标准 Go 1.25.1+（本次使用版本见 validation/build-info.json）。所有直接使用的第三方依赖已 vendor，无需联网下载：

```bash
cd /path/to/bundle/source/pqcert/pure-pq
GOTOOLCHAIN=local GOPROXY=off CGO_ENABLED=0 /path/to/go1.25.1/bin/go build -mod=vendor -o /tmp/pure-pq .
```

将 pure-pq 换成其余工具目录即可。标准 Go 1.25 工具链不包含 TLS 混合补丁，不能拿它替代网关用的 Go 1.22.12。重新生成的证书有随机密钥和时间戳，证书文件/压缩包哈希不应期待逐字节相同。

仓库侧打包入口为 `packaging/build_gateway_release.py`：指定 `--tls-goroot`、`--pq-goroot` 和可用模块缓存 `--modcache`，先构建 staging，再运行 `packaging/validate_gateway_release.py` 实测，最后用 `--seal` 生成完整性清单和压缩包。默认禁止覆盖现有 staging，可用新的 `--output` 目录重建。打包和验收脚本随本包源码一并提供。
