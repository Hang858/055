# 能力与证书对应说明

## 项目阅读结论与本次交付

已检查根目录 README/构建文档、tls-hybrid 服务端/客户端/自测、Go TLS 补丁、pqcert 五个入口及相关证书生成和验签逻辑；同时检查了 pqtls-1.3 和附带压缩包服务端入口。

项目包含两个交付方向：证书工具和 TLS 协议库。`tls-hybrid` + 补丁 Go 1.22.12 是现有可构建 TLS 路径。其原 server 是演示应用，不能转发业务。本次增加 `gateway/`，使用同一补丁协议库实现固定后端 HTTPS 反向代理，提供静态二进制、JSON 配置、严格校验的 probe、现场 PKI 生成和演示后端。

`pqtls-1.3` 及 cloudflare 压缩包入口使用另一套 ProtocolType/QuantumSupportAKEX 扩展，不作为本交付运行入口；未将其未经验证的二进制混入网关。HQC 需要额外 cgo/liboqs，本交付采用不依赖动态库的 Kyber 构建，不含 HQC。PQC 浏览器不在本次范围。

## 网关实际能力

| 项目 | 本交付支持 |
|---|---|
| 入站协议 | HTTPS / TLS 1.3，HTTP/1.1 |
| 入站密钥交换 | 项目既有 SM2+Kyber / X25519+Kyber，512/768/1024 六个 Draft00 组 |
| 运行证书 | 默认 ECDSA-P256 X.509 CA/服务端/客户端证书；支持加载兼容的 RSA/ECDSA PEM 证书和匹配私钥 |
| 身份验证 | 客户端严格验证 CA、有效期、SAN；可配置 mTLS，网关严格验证客户端 CA/用途/有效期 |
| 后端协议 | 固定 HTTP 或 HTTPS 地址；HTTPS 强制验证后端证书，TLS 至少 1.2 |
| 业务转发 | 路径、查询串、方法、请求体、响应体及普通业务头；重新设置转发头，清除客户端伪造的 Forwarded/X-Forwarded-* |
| 运维 | JSON 配置、启动检查、协商算法日志、SIGTERM 停止、systemd 托管 |
| 未实现 | 四层 TCP 代理、透明代理、VPN、WAF、负载均衡集群、管理界面、自动续签/吊销检查、HQC、浏览器互通认证 |

网关是基于现有研究协议库整理的厂内联调交付版本，不能据此宣称达到生产密码产品认证、全链路抗量子身份认证、最终 ML-KEM/ML-DSA 标准兼容或任意 PQC 浏览器兼容。实际只把 PQ 混合 KEX 用于客户端至网关段；后端 HTTPS 通常使用传统 TLS。TLS 对称密码套件由协议库默认协商，未实现逐套件配置，因此不能由 Kyber1024 组名推出整个通信系统达到同等安全等级。

## 两类证书的对应关系

| 类别 | 生成方式 / 存放位置 | 能否直接用于本网关 |
|---|---|---|
| 运行证书 | `bin/pqc-gateway pki` / `certs-demo` 或现场 `certs` | 可以，实际加载并做转发验收；默认 ECDSA 签名，PQC 在 KEX 层 |
| pure-pq 研究链 | 原 `pqcert/pure-pq` / `certificate-tools/examples/pure-pq` | 不可以；自定义 ASN.1/OID，包含原始 Dilithium、SLH-DSA 及 Kyber 公钥 |
| sm2 混合研究链 | 原 `pqcert/sm2` / 对应 examples | 不可以直接替换；使用项目 SM2 库和自定义扩展，需专用验签/私钥处理 |
| x509-multi 研究链 | 原 `pqcert/x509-multi` / 对应 examples | 不直接用于网关；主体为 RSA X.509，PQ 数据放自定义扩展；工具未输出可直接配套加载的终端 RSA 私钥 |
| 外部公钥导入签发 | gen-pq-chain / gen-sm2-chain | 不用于本网关；使用示例 public_keys.txt，只签发外部公钥，工具没有对应终端私钥 |

原工具用 `circl/sign/dilithium/mode2/3/5` 实现格签名。虽然历史文档/日志写有“ML-DSA”，不能仅凭名称认定实现就是最终 ML-DSA；其 OID 也沿用项目实验编码。这里保留源码、算法、证书内容和输出名称，不将它们转换或重标成标准生产证书。

研究样例包含用于重复实验的私钥，只供联调，不作为正式身份。打包前重新生成样例，不沿用仓库旧证书。工具自身的一部分验签失败仅打印日志、退出码仍可能为 0，必须阅读 generation.log 中的实际验签结果，不能仅凭“全部完成”字样判定通过。

## 原证书工具使用

从解压目录执行，输出目录必须不存在：

```bash
bash ./certificate-tools.sh pure-pq /tmp/pqcert-pure-new
bash ./certificate-tools.sh sm2 /tmp/pqcert-sm2-new
bash ./certificate-tools.sh x509-multi /tmp/pqcert-x509-new
bash ./certificate-tools.sh gen-pq-chain /tmp/pqcert-import-pq-new
bash ./certificate-tools.sh gen-sm2-chain /tmp/pqcert-import-sm2-new
```

包装脚本固定正确的工作目录，使用 umask 077，收紧新私钥权限为 600，并保存 generation.log。所有工具无需 Go 即可运行。pure-pq 输出 `pq_x509_certs/`；sm2 输出 `certs_sm2/`；x509-multi 输出 `certs/`；两种导入工具输出 `certs-sample/`。

导入工具的示例输入在每次输出目录的 `data/public_keys.txt`；要签发厂内外部公钥，在新建实验工作目录中准备 data/public_keys.txt 和 work/，从 work/ 启动相应 `certificate-tools/bin/gen-*-chain`，输出到同级 certs-sample/。终端私钥应由外部公钥提供方保管，本工具不会替其生成。

## 浏览器对接参数

交给浏览器团队的内容：网关 HTTPS 域名/IP、端口、现场 ca.crt、实际启用组、必要时客户端证书/私钥。浏览器需兼容项目 Draft00 的编码及码点：

| 组 | 码点 |
|---|---|
| X25519Kyber512Draft00 | 0xfe30 |
| SM2Kyber512Draft00 | 0xfe34 |
| X25519Kyber768Draft00 | 0x6399 |
| SM2Kyber768Draft00 | 0xfe35 |
| X25519Kyber1024Draft00 | 0xfe36 |
| SM2Kyber1024Draft00 | 0xfe37 |

普通浏览器/curl 不支持这些组时会握手失败，这是默认强制 PQ 策略的预期行为。先用本包 probe 验证协议和业务，再做独立浏览器适配验证。本次没有浏览器安装包或浏览器测试结果。
