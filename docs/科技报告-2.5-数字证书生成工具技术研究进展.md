## 2.5 数字证书生成工具技术研究进展

数字证书是 PKI 体系中绑定实体身份与公钥的载体，也是 TLS、IPSec、SSH 等协议完成身份认证的信任锚点。抗量子迁移对证书工具提出了双重要求：既要能按 GB/T 20518-2018 与 X.509 规范生成传统/国密证书，也要能承载抗量子公钥与抗量子签名，并覆盖 128、256 比特两档量子安全等级。本节从标准化组织规范与产业界工具两条线索，梳理抗量子证书生成技术的发展现状。

### 2.5.1 标准化组织抗量子证书规范

**(1) NIST**

NIST 通过 FIPS 203、FIPS 204、FIPS 205 分别标准化 ML-KEM、ML-DSA 与 SLH-DSA 三类算法[76-78]，规定了公钥、私钥与签名的编码方式及固定尺寸，这是证书工具实现主体公钥、签名域与扩展字段的直接依据。在迁移层面，NIST IR 8547《Transition to Post-Quantum Cryptography Standards》将 X.509 PKI 升级列为 TLS 等协议迁移的配套工作，明确要求支持 ML-DSA 后量子签名证书、更新密码库、适配更大尺寸的抗量子密钥与签名报文，并给出 2030 年后逐步限用传统算法、2035 年全面淘汰量子脆弱公钥算法的时间规划[79]。NIST SP 1800-38 系列则提供迁移实操模板，覆盖资产盘点、密码物料清单、互操作与性能实测等环节，其中专门验证后量子 X.509 证书在 TLS 握手流程中的兼容性与工程开销[80]。在算法标识层面，NIST 在计算机安全对象注册表（CSOR）中为 ML-DSA（`2.16.840.1.101.3.4.3.17`–`.19`）、SLH-DSA（`.3.20`–`.31`）、ML-KEM（`.4.4.1`–`.3`）分配了对象标识符，成为 IETF 证书规范的算法标识来源。

**(2) IETF**

IETF 的工作可分三层。第一层是证书结构基础：RFC 5280 定义 X.509 v3 证书的字段、编码与扩展机制，抗量子证书的扩展承载方式均建立在其之上[81]；RFC 9794 统一了抗量子与传统混合密码的术语，区分纯传统、纯抗量子与 PQ/T 混合三类多算法构造，为证书与协议层的描述提供统一口径[82]。第二层是算法标识规范：RFC 9881 规定 ML-DSA 在 X.509 中的用法，明确 SPKI 中公钥为原始字节、算法参数缺省、签名值直接置于 BIT STRING，并给出证书与 CRL 中的签名算法标识[83]；RFC 9909 规定 SLH-DSA 十二个参数集的 OID 与编码[84]；RFC 9935 规定 ML-KEM 在 X.509 中的用法，使以 KEM 公钥为主体的证书也有正式标准可依[85]。三份 RFC 合起来意味着"纯抗量子证书"在算法标识与编码层面已经标准化。第三层是混合证书方向：经典与抗量子组合的复合签名证书仍处于草案阶段，draft-ietf-lamps-pq-composite-sigs 定义以单一复合算法 OID 承载组合公钥与组合签名的证书格式[86]，draft-ietf-lamps-pq-composite-kem 定义复合 KEM 证书[87]，二者尚未成为 RFC。由此形成两条工程路径：一条严格按 RFC 9881/9909/9935 生成纯抗量子证书；另一条在标准空窗期采用"经典证书 + 自定义扩展承载抗量子公钥与签名"的过渡方案，以换取与存量 PKI 的兼容性。

**(3) 国内标准**

国内证书工具的基本依据是 GB/T 20518-2018《信息安全技术 公钥基础设施 数字证书格式》，其规定与 X.509 同构，并支撑国密双证书体系，SM2 签名与 SM3 摘要由 GM/T 系列规范配套[88]。在抗量子方向，公开可见的国标与行标尚未形成与 RFC 9881/9909/9935 对等的规范，因此国内工程实现多采用"GB/T 20518/X.509 兼容结构 + 扩展字段承载抗量子材料"的方式，在保持国密合规的同时引入抗量子能力。

### 2.5.2 产业界抗量子证书工具与产品

**(1) OpenSSL**

OpenSSL 自 3.5 版本起原生支持 ML-KEM、ML-DSA 与 SLH-DSA，并支持 RFC 9881/9909/9935 规定的算法标识，可直接通过 `openssl req`、`openssl x509` 等命令生成与解析纯抗量子证书；而 3.0、3.1 等早期版本尚不识别这些算法（实测 3.0.18 对纯抗量子证书报 `unsupported`）。对于仍在使用早期 3.x 版本的环境，oqs-provider 以 provider 方式外挂 Open Quantum Safe 的算法集，可在不改动 OpenSSL 主体的前提下生成实验性后量子证书[89]。OpenSSL 的优势在于与现有 PKI 工具链同源、互操作性好，不足是对混合/复合证书尚无标准支持。

**(2) BoringSSL 与 circl**

BoringSSL 已引入 ML-KEM、ML-DSA 等抗量子原语，支撑 Chrome、Cloudflare 等大规模抗量子 TLS 实验；Cloudflare 的 circl 库则为 Go 生态提供 Dilithium、Kyber、SPHINCS+ 等实现[90]，便于在证书工具中直接调用。这类库的定位是"算法原语 + 协议集成"，证书生成仍需上层工具自行完成 ASN.1 结构组装、逐级签发与验签。

**(3) 商业 PKI/CA 与国内商密厂商**

商业 CA 软件与国内商密厂商普遍以"可插拔密码提供者"的方式扩展抗量子算法，在 SM2 双证书基础上探索 SM2 与 ML-DSA 的混合证书、抗量子网关与证书签发服务；银行等行业的试点多在测试环境中验证证书链兼容性、生成性能与协议适配性。受标准进度影响，这类产品通常同时支持"按 RFC 生成的纯抗量子证书"与"以扩展承载的混合证书"两种形态。

**(4) 学术与开源混合证书方案**

学术界提出增量扩展型、混合绑定型与差分扩展型三类混合证书格式，以及可分离、不可分离两类混合签名方案；开源实现多采用增量扩展型，即保持原证书结构与解析逻辑不变，仅以自定义扩展承载抗量子公钥与签名，以最小改动换取兼容性。该路径的代价是扩展语义缺乏标准约束，跨厂商互操作依赖约定，且抗量子签名的覆盖范围（原始 TBS 与最终证书）需要在实现中明确。

综上，纯抗量子证书的标准化已基本完成（RFC 9881/9909/9935），混合证书仍处于草案与工程约定并存的阶段；产业界形成了"OpenSSL 原生支持、oqs-provider 兼容旧版本、专用工具与 CA 扩展"的格局。对本课题而言，证书生成工具应在证书结构上兼容 GB/T 20518-2018 与 X.509，在算法标识上对齐上述 RFC，在混合形态上采用扩展承载并预留向复合签名标准迁移的能力。
