## 2. 脚本

### 2.1 脚本组成

| 文件/目录 | 作用 |
|---|---|
| `run-certtool-test-pipeline.sh` | 总入口，按版本号顺序执行全部 `ZS-*.sh`，生成 `summary.tsv` 和逐项日志 |
| `certtool-test-scripts/lib.sh` | 公共库：生成用例配置、执行 check/generate/verify、断言 PEM/OID/证书链/报告算法 |
| `certtool-test-scripts/ZS-1-*.sh` | 19 个功能与正确性用例 |
| `certtool-test-scripts/ZS-2-2 *.sh` | 性能用例 |
| `certtool-test-scripts/ZS-3-1 *.sh` | 组合覆盖用例 |

每个用例脚本都会：

1. 用 `case_config` 从 `config/` 样例生成独立 JSON 配置，输出到本用例结果目录；
2. 执行 `pqc-certtool check`、`generate`、`verify`；
3. 用 `python3`/`openssl` 检查 PEM、OID、证书链、字段、报告算法或耗时；
4. 输出该用例的 `check.json`、`generate.json`、`verify.json` 和证书文件。

### 2.2 运行方式

在测试包根目录执行全部用例：

```bash
bash run-certtool-test-pipeline.sh
```

单独执行一条：

```bash
bash 'certtool-test-scripts/ZS-1-19 私钥 PEM 文件输出测试.sh'
```

运行环境需要：Bash、Python 3、OpenSSL。

结果默认写入 `results/pipeline-<日期>-<时间>-<pid>/`，包含：

```text
summary.tsv
logs/<用例编号>.log
<用例编号>/<配置>.json
<用例编号>/<配置>.check.json
<用例编号>/<配置>.generate.json
<用例编号>/<配置>.verify.json
<用例编号>/<配置>-out/...
```

### 2.3 关键断言

`lib.sh` 里主要断言：

- `assert_pem`：文件非空，首行是预期的 `BEGIN CERTIFICATE` / `BEGIN PRIVATE KEY` / `BEGIN PQC PRIVATE KEY`；
- `assert_oid`：在 DER 中查找指定 OID；
- `assert_rsa_chain`：用 OpenSSL 校验证书链；
- `assert_report_algorithm`：检查 `report.json` 中对应证书的算法名；
- `case_run`：`verify` 返回的 JSON 中 `verified` 必须为 `true`。
