## 0. 一次性准备（只做一次）

### 0.1 进入项目根目录并确认补丁工具链存在

```sh
cd 055                      # ← 换成你本机的项目目录名（进入项目根目录）
pwd                         # 确认当前就在项目根目录
ls                          # 应看到 README.md、tls-hybrid、pqcert、tools、docs、patches 等
ls -l .build/go/bin/go      # 打过补丁的 Go 1.22.12（约 14MB）
```

- 有输出 → 继续。
- 提示"没有那个文件或目录"→ 说明工具链未构建：按 `docs/BUILD.md` 的 **A 节**重建
  （下载 Go 1.22.12 源码 → 应用 `patches/` → `make.bash`，约 3 分钟），再回到本文件。

### 0.2 编译 6 个测试程序（只做一次）

```sh
# (0) 编译用环境变量：每个"需要编译"的新终端，先执行这一段（只影响编译，运行时不需要）
export PQROOT=$PWD                      # 记下项目根目录（$PWD 是执行本条命令时所在目录）
export GOCACHE=$PQROOT/.build/gocache   # Go 编译缓存（必须可写）
export GOPATH=$PQROOT/.build/gopath
export GOFLAGS=-buildvcs=false
export GOTOOLCHAIN=local                # 禁止联网下载其它版本 Go
export PATH=$PQROOT/.build/go/bin:$PATH
go version   # 必须显示 go version go1.22.12 linux/amd64（若显示 1.22.2，说明 PATH 没生效）
# (1) 编译 4 个基础程序（命令都在子 shell 里切目录，执行完自动回到项目根目录）
( cd tls-hybrid/e2e    && go build -o ../../.build/e2e . )        # 端到端自测程序（单进程同时起服务端+客户端）
( cd tls-hybrid/server && go build -o ../../.build/server . )     # 独立服务端
( cd tls-hybrid/client && go build -o ../../.build/client . )     # 独立客户端
( cd tools/tlsbench    && go build -o ../../.build/tlsbench . )   # 性能测试工具（TLS-2-* 使用）

# (2) 编译 HQC 版本（只有需要用到 HQC-128 / HQC-256 时才编译；依赖 cgo + liboqs）
# 注意：CGO_CFLAGS / CGO_LDFLAGS 必须写成**绝对路径**（cgo 编译时的工作目录不是源码目录，
#       写 ../../.build/... 会报 oqs/oqs.h: No such file or directory），所以这里用 $PQROOT
( cd tls-hybrid/e2e && CGO_ENABLED=1 \
    CGO_CFLAGS="-I$PQROOT/.build/liboqs/include" \
    CGO_LDFLAGS="-L$PQROOT/.build/liboqs/lib -loqs" \
    go build -tags pq_hqc -o ../../.build/e2e_hqc . )
( cd tools/tlsbench && CGO_ENABLED=1 \
    CGO_CFLAGS="-I$PQROOT/.build/liboqs/include" \
    CGO_LDFLAGS="-L$PQROOT/.build/liboqs/lib -loqs" \
    go build -tags pq_hqc -o ../../.build/tlsbench_hqc . )

# (3) 校验：应列出 6 个文件（缺哪个就回到上面单独编译哪个）
ls -l .build/e2e .build/e2e_hqc .build/server .build/client .build/tlsbench .build/tlsbench_hqc
```

> **`( cd 目录 && 命令 )` 是什么意思**：括号表示在"子进程"里切目录，命令跑完自动回到项目根目录，
> 所以后续命令仍然以项目根目录为基准、不需要再 `cd` 回去。
>
> **编译报错怎么排查**：出现 `open $HOME/.cache/go-build/...: read-only file system`、
> `go.mod requires go >= 1.22.12 (running go 1.22.2)`、`go: cannot find GOROOT` 这三类报错，
> 都是因为 **(0) 段的 export 没在当前终端执行**（包括新开终端忘了重跑）——回到 (0) 重跑再编译即可。

### 0.3 准备测试证书（**必做**：仓库自带的证书已于 2026-04-15 过期，需另备有效证书）

> **仓库自带的 `tls-hybrid/server/server_root_cert1.pem` 不要覆盖**，
> TLS-1-9 第 1 步就是用这张过期证书复现"证书过期被拒绝"。新证书统一生成到 `.build/certs/` 下。

```sh
mkdir -p .build/certs
( cd .build/certs && \
  openssl req -x509 -newkey rsa:2048 -nodes -sha256 -days 3650 \
    -keyout server_root_key1.pem -out server_root_cert1.pem \
    -subj "/C=CN/O=Root Certificate/CN=Root Certificate" \
    -addext "subjectAltName=DNS:localhost,IP:127.0.0.1" && \
  openssl req -x509 -newkey rsa:2048 -nodes -sha256 -days 365 \
    -keyout other.key -out other.crt -subj "/C=CN/O=Other/CN=localhost" \
    -addext "subjectAltName=DNS:localhost,IP:127.0.0.1" )

# 校验：第一条应显示 notAfter 已过去（过期），第二条应显示到 2036 年
openssl x509 -in tls-hybrid/server/server_root_cert1.pem -noout -dates -subject
openssl x509 -in .build/certs/server_root_cert1.pem     -noout -dates -subject

# 给交叉编译产物建好目录（TLS-3-4 / TLS-3-5 直接写入，不建目录会报错）
mkdir -p dist/tls/server dist/tls/client
```

> **全文的证书约定**（照着命令里的相对路径用即可，不必记忆）：
>
> | 相对路径 | 是什么 | 怎么用 |
> |---|---|---|
> | `.build/certs/server_root_cert1.pem` 与 `server_root_key1.pem` | **有效**的服务端证书与私钥 | `e2e`、`tlsbench`、`server` 都用 `-cert`/`-key` 指它；客户端用 `-ca .build/certs/server_root_cert1.pem` 信任它 |
> | `.build/certs/other.crt` | 一张**无关的 CA** | 只在 TLS-1-9 第 2 步用（`-ca .build/certs/other.crt` 制造"不受信任"） |
> | `tls-hybrid/server/server_root_cert1.pem` | 仓库自带的**过期**证书 | 只在 TLS-1-9 第 1 步使用 |
>
> 另外：`client` 程序无论是否加 `-verify` 都会读取 `-ca` 指定的文件（读不到会 panic），所以 `-ca` 不能省略。

> **想在 Wireshark 里看到加密内容（Certificate / Alert / 应用数据明文）**：在启动命令前加
> `SSLKEYLOGFILE=.build/keys.log` 让程序导出 TLS 会话密钥，然后在 Wireshark 里设置
> **编辑 → 首选项 → Protocols → TLS → (Pre)-Master-Secret log filename** 指向 `keys.log`。
> TLS 1.3 只有 ClientHello、ServerHello（含 key_share）是明文，其余记录不解密只能看到 "Application Data"。
