### 0.3 准备测试证书（**必做**：仓库自带的证书已于 2026-04-15 过期，需另备有效证书）

> **注意：仓库自带的 `tls-hybrid/server/server_root_cert1.pem`（2026-04-15 到期）不要覆盖**，
> TLS-1-9 第 1 步就是用这张过期证书复现"证书过期被拒绝"。新证书统一生成到 `.build/certs` 下。

```sh
# (a) 有效服务端证书：文件名必须叫 server_root_cert1.pem / server_root_key1.pem，
#     因为 server / client 两个程序是按这两个固定文件名、从"当前工作目录"读证书的
mkdir -p /home/hangzhang/work/055/.build/certs/srv
cd /home/hangzhang/work/055/.build/certs/srv
openssl req -x509 -newkey rsa:2048 -nodes -sha256 -days 3650 \
  -keyout server_root_key1.pem -out server_root_cert1.pem \
  -subj "/C=CN/O=Root Certificate/CN=Root Certificate" \
  -addext "subjectAltName=DNS:localhost,IP:127.0.0.1"

# (b) 供 e2e / tlsbench 使用的有效证书对，以及一张"无关的 CA"（TLS-1-9 第 2 步用）
cd /home/hangzhang/work/055/.build/certs
openssl req -x509 -newkey rsa:2048 -nodes -sha256 -days 365 \
  -keyout fresh.key -out fresh.crt -subj "/C=CN/O=Test/CN=localhost" \
  -addext "subjectAltName=DNS:localhost,IP:127.0.0.1"
openssl req -x509 -newkey rsa:2048 -nodes -sha256 -days 365 \
  -keyout other.key -out other.crt -subj "/C=CN/O=Other/CN=localhost" \
  -addext "subjectAltName=DNS=localhost,IP=127.0.0.1"

# (c) 校验：第一条应显示 notAfter 已过去（过期），第二条应显示到 2036 年
openssl x509 -in /home/hangzhang/work/055/tls-hybrid/server/server_root_cert1.pem -noout -dates
openssl x509 -in /home/hangzhang/work/055/.build/certs/srv/server_root_cert1.pem -noout -dates

# (d) 给交叉编译产物建好目录（TLS-3-4 / TLS-3-5 直接写入，不建目录会报错）
mkdir -p /home/hangzhang/work/055/dist/tls/server /home/hangzhang/work/055/dist/tls/client
```

> **全文的证书约定**（照着命令里的路径用即可，不必记忆）：
>
> | 目录/文件 | 用途 | 谁去 cd / 怎么传参 |
> |---|---|---|
> | `/home/hangzhang/work/055/.build/certs/srv/` | **两进程用例**（`server` + `client`）的启动目录；证书文件名固定 | 必须先 `cd` 进去再启动程序；`client -ca` 指向该目录下的 `server_root_cert1.pem` |
> | `/home/hangzhang/work/055/.build/certs/fresh.crt` / `fresh.key` | `e2e`、`tlsbench` 的服务端证书/私钥 | 用 `-cert`/`-key` 传绝对路径，**不需要** `cd` |
> | `/home/hangzhang/work/055/tls-hybrid/server/server_root_cert1.pem` | 仓库自带的**过期**证书 | 只在 TLS-1-9 第 1 步使用 |
>
> 另外：`client` 程序无论是否加 `-verify` 都会读取 `-ca` 指定的文件（读不到会 panic），所以 `-ca` 不能省略。

### B.1.2 协议握手消息格式测试验证

> 本条与 TLS-1-5 都基于同一次抓包，先按下面步骤抓一次包即可。
> 抓包需要 root 权限；若机器上还没有 tshark，先执行 `sudo apt-get install -y tshark`。

#### TLS-1-4　ClientHello 消息格式验证

| 序号 | 输入及操作 | 期望结果与评估标准 |
|---|---|---|
| 1. | 【终端C】开始抓包：`sudo tshark -i lo -f "tcp port 8099" -F pcap -w /tmp/tls.pcap`（回车后持续抓包，不要关闭；若无 tshark 可用 `sudo tcpdump -i lo -w /tmp/tls.pcap "tcp port 8099"`） | 抓到回环网卡 8099 端口的流量，生成 `/tmp/tls.pcap`。 |
| 2. | 【终端B】发起一次握手（默认启用全部 6 个组）：`/home/hangzhang/work/055/.build/e2e -cert /home/hangzhang/work/055/.build/certs/fresh.crt -key /home/hangzhang/work/055/.build/certs/fresh.key -ca /home/hangzhang/work/055/.build/certs/fresh.crt -addr localhost:8099` | 客户端与服务端完成握手（输出 `✅ 客户端和服务器交互完成。`）。 |
| 3. | 【终端C】按 `Ctrl+C` 停止抓包，然后执行：`python3 /home/hangzhang/work/055/tools/tls_hello_check.py /tmp/tls.pcap`（该脚本会把 ClientHello 的字段逐项打印出来） | 输出应包含：`legacy_version: 0x0303`、`支持的协议版本(supported_versions): TLS 1.3`、`supported_groups(6 个)` 且依次为 `0xfe34 SM2Kyber512Draft00`、`0xfe30 X25519Kyber512Draft00`、`0xfe36 X25519Kyber1024Draft00`、`0xfe37 SM2Kyber1024Draft00`、`0x6399 X25519Kyber768Draft00`、`0x001d X25519`、`CH key_share: 组=0xfe34(SM2Kyber512Draft00) 长度=865，期望 865`。 |
| 4. | 【终端C】若只想用 tshark 自己看，执行：`tshark -r /tmp/tls.pcap -Y "tls.handshake.type == 1" -T fields -E header=y -E occurrence=a -E aggregator=, -e tls.handshake.legacy_version -e tls.handshake.extensions.supported_version -e tls.handshake.extensions_supported_group -e tls.handshake.extensions_key_share_group -e tls.handshake.extensions_key_share_key_exchange_length` | 字段值与上一步一致：含多个协议版本与 6 个加密交换组、`key_share` 长度 865（=SM2 公钥 65 + Kyber512 公钥 800），证明混合公钥按"经典分量 ‖ 抗量子分量"拼接。 |
