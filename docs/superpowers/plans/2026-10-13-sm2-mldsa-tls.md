# SM2 + ML-DSA TLS 身份认证实施计划

**目标：** 按任务书 128/256 比特指标和 TLS 设计报告，使客户端、网关在 TLS 1.3 握手中完成 SM2+ML-DSA 双签身份认证。

**设计：** [2026-10-13-sm2-mldsa-tls-design.md](../specs/2026-10-13-sm2-mldsa-tls-design.md)

**实现原则：** 每阶段以端到端握手或确定性的负例为验收点；抗量子身份认证策略必须失败即关闭连接，不得因证书或签名错误退回传统身份认证。使用标准 ML-DSA-44/87 后端，禁止把旧 Dilithium2/5 实现仅改名交付。

## 阶段 1：双签名原语与现状基线

- [x] 在 `gateway/hybridsig/` 编写 128/256 档位的签名、验签及破坏性输入测试。
- [x] 在补丁 Go 1.22.12 下运行模块测试及现有网关测试。
- [x] 记录现有 `crypto/tls` 抗量子签名测试无法编译：`x509.PureEdDilithium2` 未定义；不能把它当成已有通过的 TLS 能力。
- [x] 在 `gateway/hybridsig/` 补充交叉档位、公钥不匹配、DER 拼接边界和模糊输入测试。

## 阶段 2：双签证书与私钥加载

- [x] 在证书工具 `pqcert/configurable/` 明确 TLS 用 SM2+ML-DSA-44/87 样例；输出公钥、证书与两份私钥的对应关系和用途字段。
- [x] 在 TLS 证书适配层实现双签证书链独立验证及私钥持有检查；用证书工具输出构建根、叶及中间CA测试样例。
- [x] 以错误 CA、缺少 PQ 扩展、PQ 签名篡改、SM2 签名篡改、过期、SAN 不匹配、私钥不匹配测试拒绝路径。

## 阶段 3：TLS 1.3 服务端握手

- [x] 在补丁 Go `crypto/tls` 中为 SM2+ML-DSA-44/87 注册两个私用 `SignatureScheme` 码点，客户端仅在显式开启策略时声明。
- [x] 修改证书选择和 `CertificateVerify` 生成及校验，使两份签名覆盖同一待签名输入；同时接入证书链双重验证。
- [x] 网关 JSON 配置中提供身份认证策略和证书路径；客户端 probe 可指定预期签名档位并报告已验证的档位。
- [x] 运行 128/256 两档成功握手及签名缺失、篡改、算法不匹配、传统降级的失败握手。

## 阶段 4：mTLS 与交付

- [x] 在 `CertificateRequest`、客户端 `Certificate`、客户端 `CertificateVerify` 和服务端校验中实现同等双签要求。
- [x] 增加明确的传统兼容策略；抗量子强制策略下任一方不得静默降级。
- [x] 更新补丁、Linux 工具链重建说明、网关/客户端二进制安装包及 Ubuntu 20.04 使用说明。
- [x] 在本地验证两档双向认证、HQC、签名缺失与篡改、错误 CA/SAN/档位和传统降级，并保留协商码点与失败告警。
- [ ] 在厂内 Ubuntu 20.04 目标机运行交付包，记录实机验收结果。

任务书中 IPSec、SSH 是协议库的独立交付，须分别计划和验收；本计划只覆盖 TLS。
