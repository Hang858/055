# 5 研究点三 数字证书生成工具

## 5.1 引言

数字证书是公钥基础设施（PKI）的信任锚点，TLS、IPSec、SSH 等主流安全协议均以证书为载体完成身份认证与密钥绑定。当前银行信息系统使用的数字证书，无论遵循国际 X.509 标准还是我国 GB/T 20518-2018 国密双证书规范，其签名与密钥协商均建立在 RSA、ECDSA、SM2 等经典公钥算法之上，安全性依赖大整数分解、椭圆曲线离散对数等数学难题。量子计算机一旦规模化，Shor 算法可在多项式时间内破解上述难题，攻击者既能伪造合法证书、在协议握手环节实施中间人攻击，也能对长期留存的会话记录实施"先收集后解密"，从而瓦解既有的身份认证信任体系。因此，证书体系的抗量子改造是 TLS、IPSec、SSH 等协议完成抗量子迁移的前置条件。

依据课题任务书考核指标 1（银行信息系统抗量子/混合公钥证书生成工具），本课题应形成抗量子证书生成工具，支持抗量子/混合证书生成，支持 2 类抗量子密码算法，可达到 128、256 比特的量子安全等级，并以专家评审与第三方测试方式考核。指标同时要求证书格式符合 GB/T 20518-2018 与 X.509 规范。此外，任务书在课题简介与创新点 1 中提出"支持跨节点的身份认证、访问控制"与"多元异构节点抗量子密码协议互操作"，落到证书层面，即要求证书能在密码算法体系不同、证书类型不同、认证模式不同的节点之间被识别、验证与互认，这是本课题证书工具的设计边界。由此带来五方面工程难点：一是兼容性，迁移期内证书必须能被存量 PKI 与协议栈解析，不能为抗量子而重构整个信任链；二是可验证性，抗量子签名必须能被第三方独立验证，而非仅在生成端自证；三是等级可配置，同一工具需覆盖 128 与 256 比特两档参数集；四是尺寸与性能，抗量子签名与公钥尺寸较经典算法高出 1～2 个数量级，必须在证书结构与生成流程上做取舍；五是跨节点互通，迁移期内经典证书、国密证书、抗量子证书与混合证书将长期共存，证书工具须让未迁移节点仍能识别并验证证书的经典部分，同时让已迁移节点获得抗量子安全保障，并为签名型与 KEM 型两类抗量子证书（对应 Sig/KEM 异构认证）提供一致的承载方式。

本章围绕上述难点，从相关研究、方法设计与实验验证三个层面展开：5.2 节梳理抗量子签名算法、混合证书与证书工具的国内外研究现状；5.3 节提出基于双公钥、双签名与扩展承载的抗量子/混合证书生成方法，分别给出混合证书与纯抗量子证书链的设计；5.4 节依据测试大纲的 25 条用例与实测数据，从功能覆盖、量子安全等级、生成性能与跨平台适配等维度进行验证与分析；5.5 节总结本章工作与后续方向。

## 5.2 抗量子数字证书相关研究

**抗量子签名算法研究现状。** 抗量子签名算法按数学结构主要分为格基、哈希基、多变量多项式与超椭圆曲线四类。格基签名以 Dilithium/ML-DSA 为代表，已由 NIST 标准化（FIPS 204），其公钥与签名尺寸适中、签名速度快，是本课题工程实现的首选；哈希基签名以 SPHINCS+/SLH-DSA 为代表（FIPS 205），安全性仅依赖哈希函数的抗碰撞与抗原像性，假设最弱、签名尺寸最大（7.8 KB～49.9 KB），适合作为与格基形成"数学结构异构"的互补方案；多变量多项式签名与超椭圆曲线签名虽在某些参数下签名较短，但成熟度、参数选择与实现安全性仍有争议，工程落地案例较少。综合考虑算法成熟度、标准状态与实现可行性，本课题在签名类中选择 ML-DSA（Dilithium2/3/5）与 SLH-DSA（SHA2-128s/128f、192f、256s/256f）两条技术路线。

**抗量子密钥封装算法与证书中的公钥承载。** 抗量子密钥封装机制（KEM）以 Kyber/ML-KEM 为代表（FIPS 203），其公钥需以证书形式对外发布，供对端在密钥交换中封装使用。与签名算法不同，KEM 公钥进入证书后并不在证书内部执行封装运算，其量子安全等级体现为证书所承载参数集的强度，由后续协议（如 TLS 的密钥交换）实际兑现。证书工具因此必须同时支持"签名类公钥"与"KEM 类公钥"两类承载形态，这正是任务书指标中"2 类抗量子密码算法"的技术内涵。

**混合证书与混合签名研究现状。** 现有研究将混合签名分为两类：可分离混合签名将经典签名与抗量子签名分别存放、独立验签，性能好、对原有流程侵入小；不可分离混合签名采用嵌套方式，先产生经典签名、再对抗量子算法对经典签名再次签名，安全性更强但存在串行开销。混合证书格式相应地分为增量扩展型、混合绑定型与差分扩展型：增量扩展型保持原证书结构、以自定义扩展承载抗量子材料，兼容性最好；混合绑定型将两套公钥绑定在同一主体中；差分扩展型通过扩展差异字段实现多算法并存。TLS 1.3 中的混合认证研究进一步表明，客户端与服务端可分别采用签名证书或 KEM 证书，形成 Sig-Sig、Sig-KEM、KEM-Sig、KEM-KEM 四种异构认证模式，证书工具需为这些模式提供可组合的证书材料。

**证书标准与工具现状。** 标准化方面，ML-DSA、SLH-DSA 与 ML-KEM 在 X.509 中的用法已分别形成 RFC 9881、RFC 9909、RFC 9935，算法标识及公钥、签名编码均有明确规定；而经典与抗量子混合（复合）签名的组合方式仍处于草案阶段（draft-ietf-lamps-pq-composite-sigs），尚未形成统一、可互操作的强制标准。工程方面，OpenSSL、CFSSL、EJBCA 等通用工具只识别其已收录的算法标识：实测本机 OpenSSL 3.0.18 尚未收录 ML-DSA、SLH-DSA 与 ML-KEM，即使算法标识已按 RFC 对齐，`openssl x509` 仍无法加载纯抗量子证书（报 `unsupported`），仅能借助 `openssl asn1parse` 做通用 ASN.1 解析。这说明在标准落地与工具生态尚未同步的迁移阶段，需要专用工具来完成抗量子证书的生成、解析与验签，而不能完全依赖通用 PKI 工具。

综上，现有研究在算法层面已具备可用基础，但在工程层面仍缺少一套同时满足"混合与纯抗量子并存、128/256 两档等级、可被第三方验证、跨平台可运行"的证书生成工具，这正是本章要解决的问题。

## 5.3 基于双公钥双签名扩展的抗量子/混合证书生成方法

### 5.3.1 研究动机与目的

迁移期证书工具的设计动机来自四组现实约束。第一，存量兼容约束：银行现有 PKI 的根证书、中间 CA、终端证书全部基于 RSA 或 SM2，协议栈也按标准 X.509 解析证书，任何"推倒重来"的方案都无法落地，因此抗量子能力必须以增量的方式嵌入既有结构。第二，第三方可验证约束：抗量子签名若只在生成端自证，就无法支撑第三方测评与跨机构互认，因此签名必须覆盖可复现的证书内容（TBS），并可被独立验签。第三，尺寸与性能约束：以 128 比特档为例，ML-DSA-44 公钥为 1312 字节、签名 2420 字节，SLH-DSA-SHA2-128s 签名达 7856 字节，较 RSA-2048 的 256 字节签名高出一个数量级以上；若把所有抗量子材料直接塞入证书主体公钥字段，将破坏标准解析逻辑并显著放大证书体积。第四，跨节点互通约束：不同机构、不同场景的抗量子迁移进度与算法选型并不一致，经典证书、国密证书、混合证书与纯抗量子证书将长期共存，证书工具生成的证书必须能被密码能力不同的节点分别解析与验证，否则跨节点身份认证无法成立。基于这四组约束，确定本方法的目标为：一套工具同时产出混合证书链、纯抗量子证书链与外部公钥导入签发三类材料；覆盖 128、192、256 三档参数集（任务书要求 128 与 256）；生成结果可被标准库或工具自身正确解析与验签；工具可跨 Linux/Windows 平台编译运行；并为跨节点身份认证提供证书材料支撑。

### 5.3.2 方法总览

方法遵循四条设计原则：**兼容优先**，混合证书完整保留 X.509 v3 基础字段与经典主体公私钥，仅以自定义扩展承载抗量子材料；**双模并存**，混合路径面向迁移期，纯抗量子路径面向最终形态与验证需求；**等级可配**，算法参数集按 128/192/256 三档组织，由配置选择；**可验证**，签名对象统一为证书 TBS 的 DER 编码，验签不依赖生成时的内存状态。

工具体系按五层组织：算法抽象层（`PQAlgorithm` 枚举，封装 Dilithium、SLH-DSA、Kyber 的密钥生成、序列化与签名接口）、密钥管理层（`PQKeyPair` 统一容器，同时容纳签名公私钥、KEM 公私钥与序列化公钥字节）、证书模板层（基于 X.509 v3 构造模板，注册承载抗量子公钥与抗量子签名的两个私有扩展）、证书签发层（根 CA、中间 CA、终端实体的分层签发，先完成经典签发再追加抗量子扩展与签名）、验证与持久层（PEM 持久化、证书链合法性校验、证书信息格式化输出）。在此架构上形成五个可执行工具与三类证书形态，如表 5-1 所示。

### 5.3.3 方法设计一：混合证书——经典主体、扩展承载与双公钥双签名

混合证书面向迁移期，目标是"不改动标准解析逻辑的前提下叠加抗量子能力"。其结构是在标准 X.509 v3 证书之上增加两个自定义扩展：`1.3.6.1.4.1.54321.1.1` 承载抗量子公钥（签名公钥或 KEM 公钥，按算法类型取其一），`1.3.6.1.4.1.54321.1.2` 承载抗量子签名值；证书主体公钥、签名域与签名算法标识仍为 RSA 或 SM2，从而对存量解析器完全透明。扩展字段设计如表 5-3 所示。

**表 5-3 混合证书扩展字段设计**

| 扩展 OID | 含义 | 内容 | 关键性 |
|---|---|---|---|
| `1.3.6.1.4.1.54321.1.1` | 抗量子公钥 | 抗量子公钥的二进制序列化字节（如 Kyber-512 公钥 800 字节、Dilithium2 公钥 1312 字节） | 非关键 |
| `1.3.6.1.4.1.54321.1.2` | 抗量子签名 | 对证书原始 TBS 的抗量子签名（如 Dilithium2 签名 2420 字节） | 非关键 |

签发流程分四步。第一步，按标准模板生成含抗量子公钥扩展、但尚未含抗量子签名扩展的证书，由经典私钥完成标准签发；第二步，解析该证书并取出其 `RawTBSCertificate`，得到"原始 TBS"；第三步，用抗量子签名私钥对原始 TBS 的 DER 编码签名；第四步，把抗量子签名作为 `1.3.6.1.4.1.54321.1.2` 扩展追加进模板，重新编码得到最终证书。验签流程与之对称：先按标准流程逐级验证经典签名（根自签、中间由根签发、终端由中间签发），再从扩展中取出抗量子公钥与抗量子签名，对生成时保存的原始 TBS 执行抗量子验签，两者均通过才判定证书可信。

该设计的安全性来自两套公钥互为对方签名的覆盖对象。经典签名覆盖的 TBS 已包含抗量子公钥扩展，因此替换抗量子公钥会破坏经典签名；抗量子签名覆盖的原始 TBS 包含经典主体公钥与全部标准字段，因此替换经典公钥会破坏抗量子签名。攻击者若要伪造或替换任一套公钥，必须同时攻破经典签名与抗量子签名；即使经典签名被量子计算攻破，抗量子签名仍然有效，证书的完整性与身份绑定依然成立。这一性质对应混合签名研究中的"存储可分离、绑定不可分离"折中：两套签名在证书中分域存放（可分离，便于独立验签与渐进部署），但两套公钥分别处于对方签名的覆盖范围内，形成互相绑定（不可分离，防止单侧替换）。需要说明的是，抗量子签名的覆盖范围是"追加抗量子签名扩展之前的原始 TBS"，而非最终证书的完整内容，因此两套签名覆盖的字节范围并不相同，验签时须使用生成阶段保存的原始 TBS。兼容性方面，混合证书可被标准 `crypto/x509` 与国密 `gmx509` 正常生成、解析和链验签，实测 `openssl verify` 输出 `end-entity.pem: OK`。从跨节点视角看，混合证书的"经典主体 + 抗量子扩展"结构恰好对应迁移期两类节点的能力差异：尚未迁移的节点按标准 X.509 解析主体公钥与经典签名，仅凭经典字段即可完成链验证与身份认证；已迁移的节点在经典链验证通过后，再从扩展中提取抗量子公钥与签名做二次验签，从而以同一张证书同时满足两类节点的验证需求。证书承载的抗量子公钥按算法类型分为签名公钥与 KEM 公钥两类，分别构成"签名型用户证书"与"KEM 型用户证书"，可为协议层 Sig-Sig、Sig-KEM、KEM-Sig、KEM-KEM 四种异构认证模式提供证书材料；单张证书同时承载两类公钥的能力属于跨节点认证的增强项，列为本方法后续工作。

该方法也存在两点工程局限，需要在测试与部署中明确。其一，抗量子签名覆盖的是"追加签名扩展之前"的原始 TBS，第三方若只持有最终证书文件，无法直接复验，必须由生成端保存原始 TBS 或按同一规则重建；其二，扩展值为裸字节，未做 ASN.1 封装，且承载抗量子材料的扩展 OID 为私有约定——复合签名标准尚在草案阶段，待其定稿后需做一次迁移对齐。

### 5.3.4 方法设计二：纯抗量子证书链——自建 ASN.1 结构与逐级签发

纯抗量子证书面向"无经典算法残留"的验证需求与最终形态。由于通用库不支持以私有 OID 标识的抗量子算法，本方法按 X.509 v3 的字段顺序与编码规则自行定义 `TBSCertificate`、`Certificate`、`SubjectPublicKeyInfo`、`Extension` 等 ASN.1 结构，并以 `encoding/asn1` 完成 DER 编解码。证书主体公钥直接为抗量子算法公钥：签名类链的主体公钥为 ML-DSA 或 SLH-DSA 公钥，KEM 类用户证书的主体公钥为 Kyber 公钥；主体公钥算法标识、签发者签名算法标识与顶层签名算法标识均使用对应抗量子算法的标准 OID（ML-DSA-44/65/87 为 `2.16.840.1.101.3.4.3.17/18/19`，SLH-DSA-SHA2 六个参数集为 `2.16.840.1.101.3.4.3.20`～`.25`，ML-KEM-512/768/1024 为 `2.16.840.1.101.3.4.4.1/2/3`，分别对应 RFC 9881、RFC 9909、RFC 9935）。扩展区仅保留标准 `basicConstraints` 与 `keyUsage`，分别用于标识 CA 与路径长度、数字签名/证书签发用途。

证书链采用根证书、中间证书、用户证书三级结构，根证书自签，中间证书由根签发，用户证书由中间签发；每一级签名均为"对下级证书 TBS 的 DER 编码做抗量子签名"，验签时逐级用签发者公钥验证下级 TBS。工具共构造五条纯抗量子链，覆盖两档等级与两类数学结构，配置如表 5-4 所示。

**表 5-4 纯抗量子证书链配置**

| 链 | 根证书 | 中间证书 | 用户证书 | 等级 |
|---|---|---|---|---|
| 1 | ML-DSA-44 | ML-DSA-65 | 公钥为 Kyber-512（KEM） | 128 |
| 2 | ML-DSA-44 | ML-DSA-65 | ML-DSA-44 | 128 |
| 3 | SLH-DSA-SHA2-128s | SLH-DSA-SHA2-128s | SLH-DSA-SHA2-128s | 128 |
| 4 | ML-DSA-87 | ML-DSA-87 | 公钥为 Kyber-1024（KEM） | 256 |
| 5 | SLH-DSA-SHA2-256s | SLH-DSA-SHA2-256s | SLH-DSA-SHA2-256s | 256 |

该路径的意义有三点：一是可在不受经典算法约束的条件下，验证抗量子签名与 KEM 公钥在证书结构中的完整承载与逐级签发；二是为协议层提供"纯抗量子"证书材料，与混合路径形成对照；三是暴露了标准工具生态的边界——算法标识虽已按 RFC 9881/9909/9935 对齐，但本机 OpenSSL 3.0.18 尚未收录这些算法，实测 `openssl x509` 仍无法加载此类证书，而 `openssl asn1parse` 可正常解析其 ASN.1 结构；要让通用工具直接解析与验签，需 OpenSSL 3.5 及以上或同类支持这些 RFC 的实现，这也是本方法自带解析与验签能力的原因。此外，针对"用户私钥不出域"的签发场景，方法提供外部公钥导入路径：从外部公钥文件中读取 SM2 或 ML-DSA 公钥，生成由本地根证书签发的用户证书，用户私钥始终由对接方持有。

## 5.4 实验验证与结果分析

实验环境为 Ubuntu 24.04（x86-64），测试机为 Intel Core i7-8750H、16 GB 内存；证书工具使用 Go 1.25.1 与 Cloudflare CIRCL 密码库编译，协议侧工具使用打补丁的 Go 1.22.12 工具链。测试依据《抗量子证书生成工具测试大纲》执行，共 25 条用例，分为功能测试（19 条）、性能测试（3 条）与兼容性测试（3 条）。

### 5.4.1 评估指标

围绕任务书考核指标，设定六项评估指标：**功能覆盖度**，是否覆盖混合证书、纯抗量子证书、外部公钥导入三类形态；**算法与等级覆盖**，是否覆盖两类抗量子算法（KEM 类与签名类）及 128/256 两档等级（并验证 192 档的可扩展性）；**字段与扩展正确性**，证书版本、序列号、主体、颁发者、有效期、Key Usage、Basic Constraints 及抗量子扩展是否可被正确写入与提取；**验签通过率**，经典链验签、抗量子签名验签、纯抗量子链逐级验签是否全部通过；**生成性能**，不同算法组合下密钥生成与证书生成的单次耗时；**跨平台适配**，Linux 原生编译运行与 Windows 目标平台交叉编译是否成功。

## 5.5 本章小结

本章围绕任务书考核指标 1 以及课题简介、创新点 1 提出的"支持跨节点的身份认证"要求，完成了抗量子/混合公钥证书生成工具的研究与实现，主要工作与结论如下。

第一，提出并实现了基于双公钥、双签名与扩展承载的混合证书方法。以自定义扩展承载抗量子公钥与抗量子签名，保持经典主体与标准解析逻辑不变；两套公钥分别处于对方签名的覆盖范围内，形成单侧不可替换的互相绑定，使证书在经典签名被量子攻破后仍可依赖抗量子签名保持可信。混合证书可被标准 X.509 工具链解析与验签，满足迁移期兼容性要求。

第二，实现了纯抗量子证书链与外部公钥导入签发。按 X.509 v3 结构自行编码，主体公钥直接为抗量子算法公钥，根、中间、用户三级逐级抗量子签发与验签，覆盖 ML-DSA、SLH-DSA 与 Kyber 三类算法、128 与 256 两档等级（并支持 192 档），同时支持用户私钥不出域的外部公钥签发场景。

第三，依据测试大纲完成 25 条用例验证。功能类用例全部通过：混合证书（RSA、SM2 两种经典分量）、纯抗量子证书（5 条链）、外部公钥导入均正确生成、可解析、可验签；抗量子扩展字段可写入与提取；传统链、抗量子签名、纯抗量子链三条验签路径均通过。跨平台方面，五个工具在 Linux 与 Windows 目标平台均编译成功。指标要求的"支持抗量子/混合证书生成、支持 2 类抗量子密码算法、达到 128/256 比特量子安全等级"均已满足。

第四，在跨节点支撑方面，混合证书使未迁移节点仅凭经典字段即可完成验证、已迁移节点可追加抗量子验签，外部公钥导入签发支持用户私钥不出域的跨机构签发场景，为任务书提出的"跨节点身份认证、访问控制"提供了证书侧材料。

本章工作仍有三点局限与后续方向：其一，纯抗量子证书的算法标识已按 RFC 9881/9909/9935 对齐，但混合证书承载抗量子材料的扩展仍为私有 OID（复合签名标准尚在草案阶段），后续需跟随标准并在保持向后兼容的前提下完成迁移；其二，混合证书的抗量子签名覆盖"原始 TBS"，第三方仅凭最终证书文件无法直接复验，后续可通过预置空扩展占位、签名后回填的方式，使最终证书文件本身即可复验；其三，证书工具尚未引入编码类（如 HQC）等更多数学结构的抗量子算法；跨节点的 Sig/KEM 异构认证尚未端到端打通——协议侧要求证书以独立算法标识分别承载 KEM 公钥与签名公钥，而当前工具在一张证书中只承载其中一类，后续需补充 KEM 公钥的独立承载字段并完成双侧联调，方能支撑 KEM-KEM、KEM-Sig 等异构认证模式；此外，不同机构根证书的双向互认（交叉认证）尚未实现，也是跨节点认证需要补齐的一环。
