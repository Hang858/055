# ML-KEM 适配与矩阵回归（阶段 6）

日期：2026-11-22
对应标准：NIST FIPS 203（ML-KEM）

## 1. 适配方式

ML-KEM 由 Go 标准库 `crypto/mlkem` 实现，作为 `pqc` 的 Go 后端注册：

- `ML-KEM-768`：OID `2.16.840.1.101.3.4.4.2`，pk 1184 / ct 1088 / sk 64 / ss 32；
- `ML-KEM-1024`：OID `2.16.840.1.101.3.4.4.3`，pk 1568 / ct 1568 / sk 64 / ss 32；
- `pqc.Lookup` 先查 Go 后端，再查 C 注册表；
- `pqc.All/ByOID` 同时覆盖 C 算法和 Go ML-KEM；
- GOROOT 的 `crypto/pq` 同步了同一套 Go 后端，`myx509` 通过 OID 找到 ML-KEM。

Go 1.25 只提供 768/1024，没有 ML-KEM-512；本轮不伪造 512。

## 2. TLS 路径

### 2.1 KEX / ServerKeyGen

`Config.KEMTLSKEXAlg`（应用环境变量 `KEMTLS_KEX_ALG`）选择：

- 空：Kyber768（保持旧行为）；
- `ML-KEM-768` / `ML-KEM-1024`：混合 KEX 和 ServerKeyGen 使用 ML-KEM。

`pq_kex.go` 统一了 Kyber 与 ML-KEM 的 keygen/encaps/decaps，替换了
`handshake_server_tls13.go`、`handshake_client_tls13.go`、`handshake_client.go`
里的 CIRCL Kyber 硬编码。ServerKeyGen 的长度校验也改为按算法取尺寸。

### 2.2 KEM 证书

`Config.KEMTLSKEMAlg`（`KEMTLS_KEM_ALG`）选择证书 KEM 算法。`pqcertlab` 用
`-kem-oid 2.16.840.1.101.3.4.4.2`（768）或 `.3`（1024）生成 KEM 证书；
`myx509` 通过 `.1.4` OID 找到 ML-KEM。

- ML-KEM-1024 + HRR/ServerKeyGen 与 KEM 证书组合。

## 4. 边界

- 混合 KEX 仍是私有 `pqPublicKey` 扩展，不是标准 `X25519MLKEM768` key_share；
- ML-KEM 证书认证仍是私有 KEM 证书，不是标准 TLS 证书；
- ServerKeyGen/HRR 的部分长度检查仍按算法查表，换新算法要同时更新 `pqKEXSizes`；
- 没有 ML-KEM-512；
- 没有做性能/带宽的论文口径测量。

## 5. 应用

补丁：`packaging/tls-source/patches/mlkem-adaptation.patch`

顺序（在原有 8 个补丁之后）：

```bash
patch -p1 < ...
patch -p1 < kem-encapsulation-message.patch
patch -p1 < mlkem-adaptation.patch
```

`pqc` 模块的 Go 后端直接随源码提交；GOROOT 侧同步在
`crypto/pq/pq.go` + `crypto/pq/mlkem.go`。

环境变量示例：

```bash
KEMTLS_KEX_ALG=ML-KEM-768
KEMTLS_KEM_ALG=ML-KEM-768
KEMTLS_KEM_KEY=pqcerts/end-entity-pq-key-KEM.bin
```
