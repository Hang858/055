# 证书链 PQ 签名验证（阶段 3）

日期：2026-11-20
对应论文：第 4 章 4.2（混合 X.509、KEM+Sig 证书链）

## 1. 问题

改造前 `myx509` 的“双签名”只签了一份手工拼的 TBS，而且：

- TBS 不包含任何扩展，PQ/KEM 公钥、算法 OID 都没被 PQ 签名覆盖；
- `VerifyQuantumSignature` 只在演示函数里调用，TLS 握手只走标准 `x509.Verify`；
- `pqcertlab` 生成的实验证书根本没有 `.1.2` PQ 签名扩展。

因此链上只有经典签名在起作用，PQ 维度没有可验证的信任链。

## 2. 规范化签名输入（CSI）

新增 `crypto/myx509.CertificateSigningInput`，对已解析证书编码：

```
SEQUENCE {
  Version, SerialNumber, SignatureAlgorithm,
  Issuer, Subject, NotBefore, NotAfter, SubjectPublicKeyInfo,
  Extensions  // 除 .1.2（PQ 签名本身）以外的全部扩展
}
```

- 包含 PQ 公钥 `.1.1`、KEM 公钥 `.1.0`、算法 OID `.1.3`/`.1.4`；
- 排除 `.1.2`，避免 PQ 签名覆盖自身；
- 经典签名仍覆盖最终完整证书（含 `.1.2`），两个维度都绑定证书语义。

生成采用两阶段：

1. 先创建**不带 `.1.2`** 的原型证书，取 CSI，用签发者 PQ 私钥签名；
2. 把 `.1.2` 加入模板，再用 RSA 私钥签最终证书。

验证方从最终证书重算 CSI（过滤 `.1.2`），用父证书 `.1.1` 公钥验证。

## 3. 链验证

新增：

```go
func VerifyCertificateChainPQ(chain, roots []*x509.Certificate) error
```

- `chain` 按叶子到根排列；链顶证书的签发者从 `roots` 里按 `RawIssuer == RawSubject` 查找；
- 自签名根用自身 `.1.1` 验证；
- 每张证书用 `.1.2` + 父证书 `.1.1` + 自身 `.1.3` 算法验证。

TLS 配置新增：

```go
PQRoots                   []*x509.Certificate
RequirePQCertificateChain bool
```

默认关闭，旧证书和标准 TLS 行为不变。开启后：

- 客户端在 `verifyServerCertificate` 标准验证通过后验证服务端链；
- 服务端在 `processCertsFromClient` 后验证客户端链（要求客户端证书非空）。

## 4. 证书生成

`pqcertlab` 现在生成双签名证书：

- 根证书 `.1.1` = 根 PQ 公钥，`.1.2` = 根 PQ 私钥自签；
- 服务端/客户端叶证书 `.1.1` = 叶 PQ 公钥，`.1.2` = 根 PQ 私钥签名；
- KEM 证书同时保留 `.1.0`/`.1.4`；
- 新增 `-bad-pq`：叶证书 PQ 签名故意用一次性错误密钥，经典签名保持有效，用于负例。

## 5. 测试

| 场景 | 结果 |
|---|---|
| KEM 证书（21）+ PQ 链开启 | 握手成功，应用数据正常 |
| 签名证书（11，Dilithium2）+ PQ 链开启 | 握手成功 |
| 签名证书（11，SLH-DSA-SHA2-128s）+ PQ 链开启 | 握手成功 |
| 服务端叶证书 `-bad-pq` | 客户端报 `PQ 签名验证失败`，握手失败 |
| 客户端叶证书 `-bad-pq` | 服务端报 `PQ client certificate chain: ... PQ 签名验证失败` |
| `-bad-pq` 证书的经典链 | `openssl verify` 仍为 OK，证明失败来自 PQ 维度 |
| `go test crypto/myx509 -run TestPQCertificateChain` | PASS（含篡改 `.1.2` 负例） |
| 旧证书、未开启 `KEMTLS_PQ_CHAIN` | 握手正常，保持兼容 |

## 6. 边界

- 需要显式提供 `PQRoots`（应用环境变量 `KEMTLS_PQ_ROOT`，默认 `pqcerts/root-ca.pem`）；
- 实验室 `pqcertlab` 只有根→叶两层，没有中间 CA；`VerifyCertificateChainPQ` 支持任意长度链，但未用三层链实测；
- `myx509` 里旧的 `generateRootCA` 等演示函数仍使用旧的“无扩展 TBS”，生成的新证书不会被新验证器接受；TLS 测试已改用 `pqcertlab`；
- 证书链 PQ 验签只解决“链上 PQ 签名可信”，不改变 KEM 认证/密钥调度边界。
