# AHS 两阶段认证握手（阶段 5）

日期：2026-11-20
对应论文：FA-TLS 第 3.3 节和 Appendix A 的 two-stage key schedule。

## 1. 改动

### 1.1 新增 AHS 密钥阶段

`crypto/internal/fips140/tls13` 新增：

```go
HandshakeSecret.AuthenticatedHandshakeSecret(kemSecret []byte) *AuthenticatedHandshakeSecret
AuthenticatedHandshakeSecret.ClientAuthenticatedHandshakeTrafficSecret(transcript)
AuthenticatedHandshakeSecret.ServerAuthenticatedHandshakeTrafficSecret(transcript)
AuthenticatedHandshakeSecret.MasterSecret()
```

推导：

```
dHS  = DeriveSecret(HS, "derived")
AHS  = HKDF-Extract(salt=dHS, IKM=kemSecret)
cahs = DeriveSecret(AHS, "fa c ahs traffic", TA)
sahs = DeriveSecret(AHS, "fa s ahs traffic", TA)
dAHS = DeriveSecret(AHS, "derived")
MS   = HKDF-Extract(salt=dAHS, IKM=0)
```

应用密钥从 `MS` 派生，Finished 用 `cahs`/`sahs` 作为 base key。

### 1.2 握手顺序

KEM 认证模式（Sig-KEM、KEM-Sig、KEM-KEM）改为：

```
ClientHello
ServerHello + EncryptedExtensions + CertificateRequest + Certificate + CertificateVerify
        （服务器第一飞行不发 Finished）
Client Certificate/CertificateVerify + [type 252]
        （双方安装 AHS）
Client Finished（AHS）
Server Finished（AHS）
SessionTicket（应用密钥）
```

Sig-Sig 和 ClassicAKE 保持 TLS 1.3 原顺序：服务器 Finished 在前，客户端 Finished 在后。

### 1.3 应用密钥

- AHS 模式：`MS = AHS.MasterSecret()`，应用流量密钥、exporter、resumption 都从 MS 派生；
- 不再使用 `kemFinishedHash` 或 `WithKEMSecret` 把 KEM 秘密额外混入 master；
- 服务器在发送自己的 Finished 后派生应用密钥并读取客户端 Finished；
- 客户端发送自己的 Finished 后读取服务器 Finished，再派生应用密钥。

## 2. 测试

| 场景 | 结果 |
|---|---|
| Sig-Sig | PASS（保持原 TLS 1.3 顺序） |
| KEM-KEM | PASS（AHS，两段秘密） |
| Sig-KEM | PASS（AHS，ss_server） |
| KEM-Sig | PASS（AHS，ss_client） |
| 同构协商矩阵 | 12/12 PASS |
| 签名矩阵 | 10/10 PASS |
| AHS 单元测试 | PASS |
| Sig-KEM 服务端 KEM 私钥错误 | 失败（AHS 下 MAC/Finished 不匹配） |
| KEM-Sig 客户端 KEM 私钥错误 | 失败 |

## 3. 边界

- 还没有把 KEM 密文改成独立的 `KEMEncapsulation` 消息；当前仍复用客户端
  `Certificate` 的 `persistentCiphertextKEM` 字段和服务器 `type 252`。
- 服务器在 KEM 模式下仍发送 RSA `CertificateVerify`（TLS 1.3 证书认证要求），
  不是纯 KEM 认证。
- AHS 模式没有启用 0-RTT；会话恢复仍走原有 PSK 路径，未做 AHS 专用测试。
- QUIC 路径只做了密钥安装，未做 QUIC 端到端测试。
- 证书链 PQ 验签未与 AHS 四模式做组合矩阵。
