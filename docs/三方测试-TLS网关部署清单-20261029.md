## 8. 系统级 systemd（需要 root）

当前是 xgs 的用户级服务。三方工具如果通过 `sudo systemctl restart pqc-gateway-hybrid` 管理网关，需要先执行一次：

```bash
sudo /opt/pqc-gateway-hybrid/scripts/install-managed-systemd.sh
```

或在开发机执行：

```bash
ssh -t xgs@192.168.2.165 'sudo /opt/pqc-gateway-hybrid/scripts/install-managed-systemd.sh'
```

脚本会停掉用户级服务、释放 8443/8444/8445/9000，把四个 unit 安装到 `/etc/systemd/system/` 并启动。之后：

```bash
sudo systemctl status pqc-gateway-hybrid
sudo systemctl restart pqc-gateway-hybrid
```

## 9. 三方模板填法

`../` 是“上一级目录”。配置文件在 `/opt/pqc-gateway-hybrid/config/` 下，所以 `../certs/44/server.crt` 解析成 `/opt/pqc-gateway-hybrid/certs/44/server.crt`。下面全部用绝对路径，避免基准目录不同导致解析错误。

```ini
tls.execution_mode=ssh
tls.host=192.168.2.165
tls.port=22
tls.username=xgs
tls.password=（现场提供；需要能 sudo 时填 sudo 密码）
tls.known_hosts_file=/home/xgs/.ssh/known_hosts
tls.config_file=/opt/pqc-gateway-hybrid/config/gateway-managed.json

auth_profiles.sm2-mldsa-44.cert=/opt/pqc-gateway-hybrid/certs/44/server.crt
auth_profiles.sm2-mldsa-44.key=/opt/pqc-gateway-hybrid/certs/44/server.key
auth_profiles.sm2-mldsa-44.pq_key=/opt/pqc-gateway-hybrid/certs/44/server.pq.key
auth_profiles.sm2-mldsa-44.root_ca=/opt/pqc-gateway-hybrid/certs/44/root.crt
auth_profiles.sm2-mldsa-44.server_name=gateway.factory.local

auth_profiles.sm2-mldsa-87.cert=/opt/pqc-gateway-hybrid/certs/87/server.crt
auth_profiles.sm2-mldsa-87.key=/opt/pqc-gateway-hybrid/certs/87/server.key
auth_profiles.sm2-mldsa-87.pq_key=/opt/pqc-gateway-hybrid/certs/87/server.pq.key
auth_profiles.sm2-mldsa-87.root_ca=/opt/pqc-gateway-hybrid/certs/87/root.crt
auth_profiles.sm2-mldsa-87.server_name=gateway.factory.local

auth_profiles.ecdsa.cert=/opt/pqc-gateway-hybrid/certs/ecdsa/server.crt
auth_profiles.ecdsa.key=/opt/pqc-gateway-hybrid/certs/ecdsa/server.key
```

说明：

- 三个绝对目录分别是 `/opt/pqc-gateway-hybrid/certs/44`、`/opt/pqc-gateway-hybrid/certs/87`、`/opt/pqc-gateway-hybrid/certs/ecdsa`。
- 87 和 ECDSA 的独立配置分别是 `/opt/pqc-gateway-hybrid/config/gateway-managed-87.json`、`/opt/pqc-gateway-hybrid/config/gateway-managed-ecdsa.json`。
- `tls.known_hosts_file` 是后端机器上、运行三方工具的账户可读的 known_hosts 路径；如果后端就在服务器上用 xgs 运行，就是上面的值。
- 如果后端与网关同机，`tls.execution_mode=local`，`tls.host`、`tls.port`、`tls.username`、`tls.password`、`tls.known_hosts_file` 可以不填。

## 10. 已知限制

1. **纯 X25519 不支持**：网关的 `kex` 校验只接受混合/PQ 组，纯 `X25519` 会报 `unsupported PQ group "X25519"`。ECDSA 档当前用 `X25519Kyber768Draft00`。
2. **`auth_profiles` 不是网关 JSON 的格式**：`gateway-managed.json` 是单档配置；`auth_profiles` 是三方工具自己的配置段。当前用三个进程/端口覆盖三档；如果三方工具要改写 `gateway-managed.json` 后重启，只能切 44 或 87，切 ECDSA 时必须去掉 `pq_key`、`root_ca`、`server_name`。
3. **未启用双向认证**：配置里没有 `client_ca`，只验证服务端。需要 mTLS 时把 `/opt/pqc-gateway-hybrid/certs/44/root.crt` 配成 `client_ca`，并在客户端带 `/opt/pqc-gateway-hybrid/offline/44/client.crt`、`client.key`、`client.pq.key`。
4. **系统级服务尚未安装**：当前是用户级服务；需要 `sudo` 执行第 8 节脚本。
5. **证书目录 700**：只有 xgs/root 能读；三方工具若用其他账户，需要调整权限或改用 root。
